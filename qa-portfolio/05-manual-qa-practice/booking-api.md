# 02. Тестирование REST API бронирований

## Цель

Подготовить проверки публичного демонстрационного API бронирований: создание, чтение, обновление и удаление сущностей; обработка ошибок и авторизация.

**Тестовая среда:** [Restful Booker API](https://restful-booker.herokuapp.com/apidoc/index.html) · Postman · REST/JSON.

## Тест-план

| Поле | Значение |
| --- | --- |
| Объект тестирования | endpoints бронирований и авторизации |
| HTTP-методы | GET, POST, PUT, PATCH, DELETE |
| Проверяем | статус-код, тело ответа, типы данных, обязательные поля, авторизацию, граничные значения |
| Риски | API принимает некорректные даты/цены, возвращает неинформативные ошибки, нарушает целостность данных |

## Набор API-проверок

| ID | Запрос | Сценарий | Ожидаемый результат |
| --- | --- | --- | --- |
| TC-API-001 | POST /auth | Валидная авторизация | `200`, в ответе есть token |
| TC-API-002 | POST /auth | Неверный пароль | Авторизация не подтверждается |
| TC-API-003 | POST /booking | Создание бронирования с валидным телом | `200`, возвращается id созданной записи |
| TC-API-004 | GET /booking/{id} | Получение существующей записи | `200`, поля соответствуют созданным данным |
| TC-API-005 | PUT /booking/{id} | Полное обновление с токеном | `200`, ответ содержит обновлённые поля |
| TC-API-006 | PATCH /booking/{id} | Частичное обновление | `200`, меняются только переданные поля |
| TC-API-007 | DELETE /booking/{id} | Удаление с токеном | `201`, запись больше не доступна |
| TC-API-008 | POST /booking | Отсутствует обязательное поле | API возвращает контролируемую клиентскую ошибку, не 5xx |
| TC-API-009 | POST /booking | Дата выезда раньше даты заезда | API отклоняет некорректный интервал либо фиксируется дефект |

## Postman-коллекция

Файл [`postman/booking_api_collection.json`](postman/booking_api_collection.json) содержит базовые запросы и безопасные проверки статуса/структуры ответа. Перед запуском в переменную `baseUrl` подставляется адрес тестового API. Токен не хранится в репозитории.

## Шаблон баг-репорта

| Поле | Что заполняется |
| --- | --- |
| ID | например, DEF-API-001 |
| Заголовок | кратко: что сломано и где |
| Предусловия | созданная запись, токен, окружение |
| Шаги | точная последовательность запроса/действий |
| Фактический результат | ответ сервера: status, body, время ответа |
| Ожидаемый результат | поведение по документации или согласованному требованию |
| Severity / Priority | влияние на пользователя / срочность исправления |
| Вложения | скрин Postman или экспорт ответа без секретов |

## Статус

Коллекция и сценарии выполнены в публичной demo-среде. Ожидаемые результаты подтверждены; в рамках текущего прогона воспроизводимые дефекты не зафиксированы. Номера созданных записей намеренно не хранятся в репозитории, поскольку demo-среда может сбрасывать данные.
