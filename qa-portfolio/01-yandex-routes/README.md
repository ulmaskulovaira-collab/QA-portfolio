# Проект 1. Тестирование «Яндекс Маршруты» (учебный стенд)

**Спринт:** 2  
**Тип:** функциональное тестирование формы построения маршрута + расчёт стоимости/времени

## Что сделано

1. **Тест-анализ** — декомпозиция полей (Часы, Минуты, Откуда, Куда).
2. **Классы эквивалентности и граничные значения** — для всех полей ввода и временных интервалов скорости.
3. **Тест-кейсы** — покрытие валидных/невалидных значений, ведущих нулей, пробелов, регистра, расчётов.
4. **Баг-репорты** — найденные дефекты с приоритетом (критический / желательный).

## Артефакт

| Файл | Описание |
|------|----------|
| `report.pdf` | PDF-отчёт о выполненной работе |
| `test-design-cases-bugs.xlsx` | Полная рабочая таблица: тест-анализ → КЭ/ГЗ → тест-кейсы → баг-репорты |

### Структура Excel

- **Титульный лист** — данные студента, время выполнения
- **Этап 1. Тест-анализ** — декомпозиция полей
- **Этап 2. КЭ и ГЗ** — классы эквивалентности + граничные значения + тестовые данные
- **Этап 3. Тест-кейсы** — ID, название, предусловия, шаги, ожидаемый результат, статус, ID бага
- **Этап 4. Баг-репорты** — заголовок, статус, критичность, шаги, ожидаемый/фактический результат, окружение

## Примеры найденных дефектов

- Однозначные числа в полях «Часы» / «Минуты» не принимаются (красная рамка + ошибка)
- Значение 24 в поле «Часы» принимается как валидное
- Пустые обязательные поля не валидируются
- Пробелы в начале/конце адреса не обрезаются
- Неверный расчёт стоимости и времени в пути для собственного автомобиля

## Техники

- Классы эквивалентности
- Граничные значения
- Позитивные / негативные проверки
- Проверка форматирования (ведущий ноль, регистр, пробелы)
