# Заказы: Python + SQL + автотесты

Небольшой учебный проект, в котором проверяю не только ответ функции, но и то, что после оформления заказа записалось в базу. Данные и магазин вымышленные; внешние сервисы и доступы не нужны.

**Что проверяется:** расчёт суммы в копейках, состав заказа, смена статуса, пустой заказ, неверное количество, повтор товара, отсутствующий товар и покупатель, защита от «висячих» записей и обнаружение расхождения суммы с позициями. Негативные проверки дополнительно убеждаются, что ошибочная операция не оставила заказ в БД.

**Стек:** Python 3.10+, SQLite (`sqlite3`), `unittest`, SQL. Без сторонних библиотек.

## Запуск

Из папки проекта:

```bash
python -m unittest discover -s tests -v
```

Шесть тестовых методов, в том числе набор граничных случаев через `subTest`. Каждый тест поднимает собственную базу SQLite в памяти; ничего не нужно устанавливать или настраивать. `schema.sql` описывает ограничения данных, `validation_queries.sql` содержит три диагностических запроса с JOIN и агрегацией. В `shop.py` находится маленькая тестируемая модель заказа, в `tests/test_orders.py` — проверки её поведения и состояния БД.

Это **самостоятельная учебная работа для портфолио**, а не код Ozon, Greenway или Яндекса. Она показывает мой подход к тестированию данных и Python-автоматизации; тестирование физических устройств здесь не имитируется.
