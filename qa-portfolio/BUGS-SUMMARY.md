## Примеры конкретных багов (ожидаемый vs фактический результат)

Ниже — развёрнутые примеры из каждого проекта. Так удобнее показать на собеседовании, *как* оформлялся дефект.

### Пример 1. Яндекс Маршруты — валидация часов

| | |
|---|---|
| **ID** | BAGЧ_1 |
| **Критичность** | Критический |
| **Предусловия** | Открыт стенд «Яндекс Маршрут» (учебная версия) |
| **Шаги** | 1. В поле «Часы» ввести `0`<br>2. Снять фокус с поля |
| **Ожидаемый результат** | Значение принимается без ошибок. После снятия фокуса отображается с ведущим нулём (`00`) |
| **Фактический результат** | Поле подсвечивается красной рамкой, отображается сообщение: «Вы ввели некорректное время». Значение не принимается |
| **Окружение** | Windows 10, Chrome 115 |

### Пример 2. Яндекс Маршруты — граница диапазона

| | |
|---|---|
| **ID** | BAGЧ_3 |

| **Шаги** | 1. В поле «Часы» ввести `24`<br>2. Снять фокус с поля |
| **Ожидаемый результат** | Поле невалидно, сообщение: «Вы ввели некорректное время» |

## Общие выводы по дефектам

1. **Валидация ввода** — самая частая зона: границы чисел, пустые поля, тип символов (буквы/спецсимволы в числовых и карточных полях).
2. **Форматирование** — ведущие нули, trim пробелов, маска номера карты.
3. **Сценарии «счастливого пути» с ветвлениями** — бронирование без прав/карты, отмена брони, таймер ожидания.
4. **Сообщения об ошибках** — неверный текст или полное отсутствие подсказки пользователю.
5. **Регресс UI-форм** — предзаполнение и блокировка кнопки сохранения часто «отваливаются» между версиями.
