# Структура Notion для QA-документации

## Зачем нужна структура

Для сложной ERP-системы важно хранить тестовую документацию не одним списком, а по уровням: функциональная зона, сценарий, чек-лист, прогон, дефект и отчет.

Ниже пример обезличенной структуры Notion, которую можно использовать для портфолио.

## Главная страница

```text
QA-документация ERP-системы
```

Разделы:

- Карта покрытия
- Тест-планы
- Чек-листы
- Баг-репорты
- Отчеты по проверкам
- Роли и доступы
- Тестовые данные
- Регресс

## Карта покрытия

| Функциональная зона | Что проверяется | Статус покрытия |
| --- | --- | --- |
| Рабочий раздел пользователя | Доступ, список, карточка, действия | В работе |
| Роли и доступы | Видимость данных, ограничения, прямые ссылки | В работе |
| Действия с объектами | Создание, изменение, результат, история | В работе |
| Ввод идентификаторов | Ручной ввод, QR, ошибки формата | В работе |
| Остатки и количество | Ограничения, изменение результата | В работе |
| Интеграционные сценарии | Проверка доступных связей | Частично |

## Тест-планы

Поля:

- Название
- Функциональная зона
- Тип проверки
- Приоритет
- Статус
- Окружение
- Ответственный
- Дата проверки
- Ссылка на отчет

Пример названия:

```text
Регрессионная проверка рабочего сценария пользователя
```

## Чек-листы

Поля:

- Название
- Функциональная зона
- Предусловия
- Роль
- Тестовые данные
- Статус
- Связанный тест-план

Примеры чек-листов:

- Проверка доступа к рабочему разделу
- Проверка карточки объекта
- Проверка ручного ввода идентификатора
- Проверка QR-кода
- Проверка ограничений по количеству
- Проверка истории действий

## Баг-репорты

Поля:

- Название
- Серьезность
- Приоритет
- Окружение
- Роль
- Предусловия
- Шаги
- Фактический результат
- Ожидаемый результат
- Статус
- Комментарий QA

## Отчеты по проверкам

Поля:

- Название проверки
- Дата
- Окружение
- Что проверялось
- Что подтвердилось
- Что не подтвердилось
- Ограничения проверки
- Итог
- Рекомендации

## Роли и доступы

| Роль | Что должна видеть | Что не должна видеть |
| --- | --- | --- |
| Роль 1 | Свои объекты и доступные действия | Чужие объекты и закрытые действия |
| Роль 2 | Расширенный список объектов | Административные настройки |
| Роль 3 | Проверку результата | Изменение недоступных данных |

## Тестовые данные

| Тип данных | Что подготовить | Где сверить результат |
| --- | --- | --- |
| Пользователь | Роль и доступ | Раздел ролей или профиль |
| Объект | Подходящий статус | Карточка объекта |
| Количество | Доступный остаток | История или связанный раздел |
| Связанные записи | Нужные зависимости | Карточка или список |

## Принцип ведения

Каждый тестовый прогон должен отвечать на вопросы:

1. Что проверялось?
2. На каких данных?
3. Под какой ролью?
4. Что ожидалось?
5. Что получилось?
6. Есть ли дефекты?
7. Есть ли ограничения проверки?
