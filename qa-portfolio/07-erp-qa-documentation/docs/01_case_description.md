# Описание кейса

## Название

Ручное тестирование ERP-системы для производственного процесса.

## Конфиденциальность

Кейс основан на реальном коммерческом опыте. Часть информации изменена или обобщена.

В документе не используются реальные названия компании, клиента, внутренних систем, модулей, задач, сотрудников, ссылок, стендов, кода, API, базы данных и бизнес-логики.

Цель кейса — показать мой подход к тестированию и оформлению QA-документации.

## Контекст проекта

Проект представлял собой веб-ERP для производственного процесса. Система связывала несколько пользовательских зон: создание и обработку рабочих объектов, выполнение операций, работу с остатками, контроль качества, ролевой доступ и обмен данными с внешней учетной системой.

Проект был сложным для тестирования, потому что многие сценарии зависели от заранее подготовленных данных:

- роли пользователя;
- доступа к разделам;
- статуса объекта;
- связанных записей;
- остатков;
- истории операций;
- корректной настройки окружения.

## Моя зона ответственности

Я выполняла ручное тестирование и помогала поддерживать тестовую документацию.

В мои задачи входило:

- разбирать требования и описание задач;
- определять, какие данные нужны для проверки;
- проверять готовность окружения;
- проходить чек-листы;
- фиксировать результат по каждому пункту;
- описывать баги и недочеты;
- готовить короткие отчеты по итогам проверки;
- участвовать в регрессионном тестировании.

## Примеры проверяемых сценариев

- Проверка доступа пользователя к рабочему разделу.
- Проверка отображения списка доступных объектов.
- Проверка карточки объекта.
- Проверка действий, доступных только при определенном статусе.
- Проверка ручного ввода идентификатора.
- Проверка QR-кода.
- Проверка валидаций.
- Проверка ограничения по доступному количеству.
- Проверка изменения результата после действия.
- Проверка записи действия в истории.
- Проверка поведения при отсутствии данных.

## Результат

По итогам работы были подготовлены обезличенные шаблоны:

- структура тест-плана;
- чек-лист для проверки рабочего сценария;
- шаблон баг-репорта;
- шаблон отчета по проверке;
- структура QA-документации в Notion;
- подход к подготовке тестовых данных.
