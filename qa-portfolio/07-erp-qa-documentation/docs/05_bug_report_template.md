# Шаблон баг-репорта

## Название

Кратко: что сломано и где проявляется.

Пример:

```text
Результат действия не отображается в связанном разделе после успешного сохранения
```

## Окружение

- Стенд: тестовый / локальный
- Браузер: указать браузер и версию
- Роль пользователя: обезличенная роль
- Данные: тестовые обезличенные данные

## Предусловия

- Пользователь авторизован.
- У пользователя есть нужная роль.
- Есть тестовый объект в подходящем статусе.
- Есть связанные данные для проверки результата.

## Шаги воспроизведения

> Для публичного портфолио шаги должны быть обобщены. Не указывать реальные названия разделов, внутренние URL, точные бизнес-правила и данные.

1. Открыть рабочий раздел.
2. Выбрать тестовый объект.
3. Выполнить действие.
4. Перейти в связанный раздел.
5. Проверить отображение результата.

## Фактический результат

Действие визуально выполняется, но результат не отображается в связанном разделе.

## Ожидаемый результат

После успешного выполнения действия результат должен отображаться во всех связанных местах системы.

## Серьезность

Medium.

## Приоритет

Уточняется командой.

## Комментарий QA

Проверка выполнена на тестовых данных. Реальные названия разделов, объектов и деталей процесса не раскрываются из-за конфиденциальности.

## Что приложить в рабочем проекте

В реальном трекере к багу можно приложить:

- скриншот до действия;
- скриншот после действия;
- скриншот связанного раздела;
- роль пользователя;
- тестовый объект;
- время проверки;
- ссылку на окружение.

В публичное портфолио эти материалы не добавляются без обезличивания.
