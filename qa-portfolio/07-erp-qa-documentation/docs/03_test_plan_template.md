# Шаблон тест-плана

## Название проверки

Регрессионная проверка рабочего сценария пользователя.

## Цель

Проверить, что пользователь с нужной ролью может выполнить основной рабочий сценарий, а система корректно отображает данные, применяет ограничения, сохраняет результат и показывает историю действий.

## Область проверки

В проверку входят:

- доступ к разделу;
- отображение списка объектов;
- открытие карточки объекта;
- выполнение основного действия;
- проверка валидаций;
- проверка ограничений;
- проверка результата;
- проверка истории.

В проверку не входят:

- внутреннее устройство API;
- структура базы данных;
- код;
- реальные интеграционные данные;
- нагрузочное тестирование.

## Предусловия

- Есть тестовый пользователь.
- Пользователю назначена нужная роль.
- Пользователь имеет доступ к рабочему разделу.
- Есть тестовый объект в подходящем статусе.
- Подготовлены связанные данные.
- Есть место, где можно проверить результат действия.

## Тестовые данные

| Данные | Описание |
| --- | --- |
| Пользователь | Обезличенный тестовый пользователь |
| Роль | Роль, необходимая для сценария |
| Объект | Тестовый объект для проверки |
| Статус | Статус, при котором действие доступно |
| Количество | Тестовое значение для проверки ограничения |
| Комментарий | Необязательное поле для проверки сохранения |

## Основные проверки

| № | Проверка | Ожидаемый результат | Статус |
| ---: | --- | --- | --- |
| 1 | Открыть раздел под нужной ролью | Раздел открывается без ошибки доступа | Не проверено |
| 2 | Проверить список объектов | Отображаются доступные пользователю объекты | Не проверено |
| 3 | Открыть карточку объекта | Карточка открывается, данные отображаются корректно | Не проверено |
| 4 | Выполнить основное действие | Действие выполняется успешно | Не проверено |
| 5 | Проверить обязательные поля | Появляются понятные сообщения валидации | Не проверено |
| 6 | Проверить ограничение по количеству или статусу | Система не позволяет выполнить недопустимое действие | Не проверено |
| 7 | Проверить результат в связанном разделе | Результат отображается корректно | Не проверено |
| 8 | Проверить историю | Действие отображается в истории | Не проверено |

## Критерии завершения

Проверка считается завершенной, если:

- все пункты тест-плана имеют статус;
- найденные дефекты описаны;
- ограничения проверки зафиксированы;
- итог понятен для команды.

## Итог проверки

Статус: не проверено / пройдено / пройдено с замечаниями / не пройдено.

Комментарий:

```text
Кратко описать, что подтвердилось, что не подтвердилось, какие есть ограничения и что требуется дальше.
```
